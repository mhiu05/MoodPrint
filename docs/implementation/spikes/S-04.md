# S-04 — Hai local Supabase stacks độc lập

Trạng thái: **VERIFIED** trên máy phát triển hiện tại bằng CLI `2.122.1` và Docker Desktop Linux engine.

## Cấu hình đã chạy

| Stack | project_id | Workdir | API | PostgreSQL |
|---|---|---|---|---|
| Foundation | `moodprint-foundation` | repository root | `127.0.0.1:54321` | `127.0.0.1:54322` |
| Spike song song | `moodprint-spike-parallel` | `.local/stacks/spike-parallel` | `127.0.0.1:54421` | `127.0.0.1:54422` |

`scripts/dev/supabase_worktree.py` sao chép migration, seed và tests vào workdir riêng; thay `project_id` và tăng toàn bộ port theo offset. Mỗi workdir tự sinh ES256 private key riêng, không commit key. Không tạo worktree hay branch Phase 2/3 trong spike này.

## Thực nghiệm

1. Foundation tiếp tục chạy trong khi stack offset `+100` tồn tại.
2. `uv run python scripts/dev/supabase_worktree.py status --name spike-parallel --offset 100` trả exit `0`.
3. `uv run python scripts/dev/spike_parallel.py` trả exit `0` và thông báo:
   `VERIFIED S-04: two stacks have separate API/DB ports, data and ES256 signing keys.`
4. Probe tạo cùng một UUID synthetic trong hai DB với hai nickname khác nhau. Mỗi connection chỉ đọc đúng giá trị của DB đó. Probe xóa user test trong `finally`, FK cascade xóa profile.
5. Hai endpoint JWKS public đều trả khóa ES256; tập `kid` không giao nhau. Không sử dụng fallback HS256.
6. Foundation pgTAP chạy sau probe: **7 files, 76 assertions, PASS**. Không reset hay dừng stack Foundation trong phép thử.
7. Sau probe, `stop --name spike-parallel --offset 100` trả exit `0`; chỉ stack spike được dừng. Kiểm tra Docker xác nhận các container Foundation vẫn healthy và không còn container của tên thử trùng port `moodprint-parallel-spike`.

## Lỗi quan sát được và cách xử lý

- CLI `2.122.1` dùng `[local_smtp]`; không dùng config `inbucket` cũ.
- Khóa local phải là JWK array có `key_ops=["sign","verify"]`, `use="sig"`, `alg="ES256"`. JWK thiếu trường thích hợp làm Auth báo `no signing key found`; factory hiện sinh đủ thông tin.
- Sau Docker Desktop restart, các container cần thời gian khởi động lại; chờ `/status` sẵn sàng trước probe.
- Thử tên stack thứ ba nhưng cùng offset `+100` bị Docker từ chối bind port `54422`. Không dừng stack đang chiếm port: tái sử dụng stack spike có sẵn. Điều này xác nhận mỗi stack đồng thời cần offset riêng.

## Kết luận

Dùng workdir `.local/stacks/<name>` với project ID, port offset và signing key riêng là fallback được duyệt và đã chạy được. Phase 2/3 sau G2 có thể dùng offset `+100`/`+200`; phải kiểm port trống trước khi start. Spike không xác nhận readiness của Phase 2/3 hay G2.
