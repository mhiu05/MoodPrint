## Kết quả thực nghiệm

| Kiểm tra | Kết quả |
|---|---|
| Signed token upload file nhỏ | Thành công; metadata size đúng |
| Upload 20 MiB, chunk 6 MiB, ngắt sau chunk đầu | Client HTTP mới lấy `Upload-Offset=6291456`, tiếp tục tới 20 MiB; download trả bytes bằng input |
| `x-signature` trên POST, HEAD, PATCH | Từng request thiếu capability bị từ chối; request hợp lệ thành công; PATCH trái phép không thay đổi bytes |
| Token ký cho key A dùng metadata key B | Bị từ chối |
| Tải lại vào object đã tồn tại | Bị từ chối; object gốc còn nguyên |
| JWT người dùng đọc, list, ghi Storage trực tiếp | Không đọc/ghi được; list không trả object |
| Anonymous đọc object private | Bị từ chối |
| Signed download URL TTL 1 giây | Dùng được trước expiry, bị từ chối sau expiry |
| Upload capability do Storage cấp | `exp` cách thời điểm hiện tại xấp xỉ 7200 giây |
| Token expiry rồi cấp lại, resume cùng upload URL | Thành công trong thí nghiệm expiry ngắn mô tả dưới đây |

### Expiry ngắn có kiểm soát

Test lấy signing configuration từ **container Storage local** vào bộ nhớ, giữ nguyên claims của capability do Storage cấp và ký lại với `exp` sau 15 giây. Signing material không được in hoặc ghi file. Capability ngắn được server chấp nhận khi tạo upload và ghi 6 MiB đầu. Sau thời điểm `exp`, HEAD bị từ chối. Test gọi gateway cấp capability mới cho cùng key, dùng client HTTP mới và **cùng TUS upload URL**, nhận lại offset 6 MiB, tải hết 20 MiB và kiểm tra toàn bộ bytes qua signed download.

Thí nghiệm này kiểm tra đường xác thực expiry thực của Storage và cách renewal hoạt động, không thay đồng hồ server, không sửa cấu hình hosted. Nó không chứng minh tài nguyên upload đã thực sự tồn tại hơn hai giờ. Lần chạy với wall-clock hơn hai giờ và smoke trên hosted vẫn phải được phân biệt trong báo cáo gate.

## Điều chỉnh dựa trên hành vi thật

1. Tài liệu kế hoạch dùng endpoint `/storage/v1/upload/resumable`. Với Storage image đang chạy, endpoint này xử lý JWT/RLS và trả 403 khi chỉ có signed capability. Signed capability phải dùng **`/storage/v1/upload/resumable/sign`**; location do server trả cũng được dùng nguyên vẹn cho HEAD/PATCH. Gateway đã được root sửa theo kết quả này. Đây là sửa đường dẫn endpoint theo server thực tế, không phải fallback sang quyền JWT rộng hơn.
2. `object_info()` với key chưa tồn tại trả HTTP 400 có `statusCode='404'`, `code='NoSuchKey'`, thay vì HTTP 404. Gateway nhận diện đúng lỗi này thành `None`, các lỗi hạ tầng khác tiếp tục là structured error. Integration test trước sửa đã fail và sau sửa pass.
3. Auth settings thực trả anonymous flag trong `external.anonymous_users`, không có top-level `anonymous_users_enabled`. Script kiểm tra hosted được sửa để dùng field thực và fail closed khi thiếu/sai shape.
