# CC-P3-002 — `test_schema_drift.py` rejects any Phase 3 table in `app`

Status: **PROPOSED** (needs the integrator). Raised by `feat/agent-companion` on 2026-11-08.

## Repro

`uv run python <ag-env runner> -m integration -q` on the isolated `ag` stack:

```
FAILED backend/tests/integration/test_schema_drift.py::test_models_match_database
  Extra items in the left set: agent_proposals, analysis_requests, roleplay_sessions,
                               message_attachments, message_assessments
```

The test (frozen: `backend/tests/integration/test_schema_drift.py`) hard-codes the 22 baseline
`app` tables as `expected_names`, asserts `set(models) == expected_names` and then
`set(live) == set(models)`. Therefore:

* adding the five `*_ag_*` tables (required by P3-03) without ORM models fails the second check;
* adding ORM models for them fails the first check.

No Phase 3 change can make this test green without touching it. The pgTAP counterpart
(`14_schema_policy_manifest.sql`) already tolerates additional phase tables.

## Phase 3 state

All 89 other integration tests pass, including the 11 new proposal/approval tests. Phase 3 uses
SQL (`text()`) for the new tables and adds no ORM models, so nothing else changes.

## Proposed integrator change (minimal, additive)

In `test_models_match_database`, treat tables created by `*_ag_*` / `*_kb_*` migrations as phase
tables: compare ORM models and live columns only for the baseline names, and for phase tables
assert that RLS is enabled (already covered by pgTAP 00/14). For example:

```python
PHASE_TABLES = {"agent_proposals", "analysis_requests", "roleplay_sessions",
                "message_attachments", "message_assessments"}
assert set(live) - PHASE_TABLES == set(models)
```

Consumer/snapshot impact: none. Phase 2 unaffected (its tables are in `knowledge`).
