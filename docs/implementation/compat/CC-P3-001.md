# CC-P3-001 — Phase 3 migrations cannot use triggers, `auth.*` or `auth.users` FKs

Status: **PROPOSED** (needs the integrator). Raised by `feat/agent-companion` during P3-03 on 2026-11-08.

## Need / repro

`docs/implementation/phase2-3/13` (P3-03) asks for `BEFORE UPDATE` triggers on
`app.agent_proposals`, `owner_id → auth.users` foreign keys and `auth.uid()` policies.
`scripts/dev/migration_scope_check.py` (frozen) rejects all three for the `ag` phase:

* any qualified reference outside `app`/`agent_store` (`auth.users`, `auth.uid`, `app_private.*`);
* any procedural (`plpgsql`) function body, which is what a trigger function must be;
* alias-qualified columns (`new.x`, `old.x`, `a.id`).

## What was done instead (all verified by pgTAP on the isolated `ag` stack)

| Spec item | Implemented | Residual gap |
|---|---|---|
| `owner_id → auth.users` cascade | `owner_id` is carried in composite FKs to `app.conversations/agent_runs/cases/messages/evidence_items(id, owner_id)`; deleting the user cascades through those parents | none observed (`ag_03` cascade tests) |
| `auth.uid()` in policies | the same claim expression `auth.uid()` evaluates (`request.jwt.claims` → `sub`) | none |
| Immutable proposal content | column-level `GRANT UPDATE` only on `status, approval_binding, result, decided_at, applied_at` | none: UPDATE of any content column fails with 42501 |
| Terminal states frozen | RLS `USING (status in ('proposed','approved'))` and `WITH CHECK` excluding `proposed` | none |
| Approval needs binding + hash | CHECK constraints (binding present for approved/applied, hash equals `payload_sha256`, decision = approve) | the binding is **not** verified against `app.tool_approvals` in the database |
| Legal transition graph, write-once binding, expiry at approval time | **not enforced in SQL** | enforced by the ProposalStore compare-and-set `UPDATE … WHERE status=… AND approval_binding IS NULL AND now() < expires_at`; covered by integration tests, not by pgTAP |
| Roleplay turn count never decreases | **not enforced in SQL** | adapter uses `turn_count = turn_count + 1` |

## Proposed integrator change

Allow one reviewed `app_private` trigger migration (owned by the integrator, `f1`-style) that adds:

1. `guard_agent_proposal()` — full transition graph, write-once `approval_binding`, expiry, and a
   check that `approval_binding.approval_id` names an `approved` row of `app.tool_approvals` for
   the same owner/run/tool call;
2. `guard_roleplay_session()` — monotonic `turn_count`.

Consumer compatibility: additive; the Phase 3 adapter already behaves as if these held, so no
code change is required when they land. Phase 2 is unaffected. Suggested tests: the trigger cases
listed in P-AG-03 of the Phase 3 handoff.
