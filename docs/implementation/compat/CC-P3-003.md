# CC-P3-003 — `test_download_url_expires` is timing-sensitive (frozen baseline test)

Status: **PR open, not merged** — https://github.com/mhiu05/MoodPrint/pull/53 (`compat/cc-p3-003-storage-expiry`
→ `mhiu05/feat-refactor`, commit `ed111af5`). Test-only; no application code.

## Finding

`backend/tests/integration/test_storage_access.py::test_download_url_expires` signed a 1 s download URL, asserted a
200 for the "live" read, slept 2 s and asserted a 4xx. In the full integration run it failed intermittently
(1 of ~121 in the Phase 3 report) and passed alone.

## Diagnosis (measured, local Storage, 2026-11-09)

A probe signed a 1 s URL, waited `d` seconds and read it once:

| delay d | status of the first read |
|---|---|
| 0.0 s | 200 |
| 0.5 s | 400 |
| 0.9 s | 400 |
| 1.2 s | 400 |
| 1.6 s | 400 |

Storage rounds the expiry to whole seconds, so a 1 s URL is usable for well under a second. Any ~0.5 s of scheduling
delay (database setup, Docker I/O, a busy CI runner) makes the **first** assertion (`checked(response, {200}, "read live
signed download URL")`) fail — before the expiry assertion is reached. The application (`StorageGateway`) and Storage
behave correctly; the test design races the clock.

A full integration run on the Phase 3 branch after the fix (`118 passed`) did not reproduce the failure either, which is
consistent with a load-dependent race rather than a logic error.

## Fix (in the PR)

Re-sign the issued capability locally — the technique the neighbouring TUS expiry test already uses — once with an expiry
in the past and once as a control with an expiry 300 s ahead. Only `exp` differs, so a refusal can only be the expiry.
No sleep, no skip, no longer window; the guarantee "an expired signed URL cannot be used" is preserved and now tested
without a race.

## Handoff

* The Phase 3 branch does **not** carry the fix (the file is frozen there; `ci_ownership` would fail the branch). Until
  the PR is merged and a new baseline tag is cut (`baseline/phase-2-3-start-rc4`), the Phase 3 CI can still flake on this
  one test; the failure signature is `read live signed download URL` returning 400.
* The integrator decides whether to merge #53 and cut rc4; the Knowledge Base branch then needs the same merge.
* Backward compatible: test-only.
