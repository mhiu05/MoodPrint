> **Kiến trúc đã chốt ngày 23/10/2026:** Python 3.12/FastAPI/Pydantic v2, SQLAlchemy 2 async + psycopg 3, Alembic/uv, Supabase PostgreSQL/Auth và OpenAI Agents SDK Python. Giữ React/Vite/TypeScript; Pydantic → OpenAPI → `frontend/src/api/generated/`. Chỉ scaffold cloud, không deploy. Evidence audit ban đầu là lịch sử, không phải trạng thái implementation mới.

**Nguyên tắc:** kiểm deterministic quyền/business logic trước, gọi model thật theo ngân sách riêng; chất lượng ngôn ngữ không thay được test SQL/policy. Test IDs dưới đây là danh mục **dự kiến triển khai** gắn vào [roadmap](07-implementation-roadmap.md), không phải test đã tồn tại. Kết quả thực sự chạy trong lượt audit được tách ở cuối.

Phase 0 tạo commands thật: `uv run --project backend ruff check backend`, `uv run --project backend mypy backend/app`, `uv run --project backend pytest backend/tests/unit backend/tests/contract`; integration/concurrency dùng PostgreSQL local/container với explicit test URL/markers. Frontend giữ npm typecheck/Vitest/build/Playwright. OpenAPI regeneration/drift bảo vệ Python→TS; không script rỗng PASS. Exact runnable commands/env/skip/block reasons ghi evidence; thiếu DB không đổi SQLite hoặc gọi skipped là PASS.

Mỗi SQL test dùng database/schema cô lập và teardown có timeout; pool/servers/workers phải close ở finally. Fixtures synthetic qua public services hoặc test seed có invariant, không bật auth bypass production. E2E baseline hiện kiểm không external requests/storage/mic; fullstack tests mới phải allowlist đúng local backend/stub, không giữ assertion “không có API request” khi đã tích hợp thật.

## Concurrency/fault integration matrix

Các ca cần schedule được bằng barriers, ghi commit order và actual side effects. Property cần assert ở database và response, không chỉ UI screenshot.

| Transaction/worker A | B chạy cạnh tranh                                 | Outcome hợp lệ                                                                               |
| -------------------- | ------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| A gửi invite B       | B gửi invite A /2 accept requests                 | Một canonical pair, ≤1 room open, đủ2 actor intents                                          |
| Accept/Send/Reveal   | Revoke MATCH/publish new/profile source delete    | B commit trước→A denied; A commit trước→dữ liệu đã commit nhưng future read bị B gate chặn   |
| Lấy memory/context   | MEM revoke/source delete                          | Không call tool/emit final với snapshot cũ sau recheck; run cancelled/failed đúng trạng thái |
| Confirm proposal     | Second confirm hoặc edited payload cùng key       | Một memory receipt; payload mismatch409; không auto approve bản mới                          |
| Insert message       | Lost ACK/network retry/second tab same key        | Một message/seq, quota consumed một lần                                                      |
| Outbox commit        | Worker crash trước emit /sau emit trước mark sent | Retry notify trùng an toàn, text fetch live auth                                             |
| Reveal grant         | Owner identity edit/block/end                     | Version-bound value, không grant sai field hoặc dùng value cũ                                |
| TTL/deletion worker  | Request/read đúng lúc expiry /restore old backup  | Read denied theo time/tombstone, không đợi sweep; restore chưa mở traffic                    |

SQL integration dùng pool riêng kiểm lock order, unique indexes và `READ COMMITTED`/explicit locks; không suy concurrency từ reducer unit test vốn tuần tự. Nếu dùng isolation khác phải ghi ADR và thay tests. Fake provider có thể cố tình gọi forbidden tool sau cancellation hoặc trả invented receipt; server vẫn deny.

## Bộ E2E MVP và khôi phục lỗi

1. **M1:** account synthetic login→mọi quyền tắt→bật AI→Mây→progress/final→reload trong phiên; chuyển bot lúc pending; stop/revoke; expired/restart báo mất phiên đúng.
2. **M2:** Gương proposal→sửa→save private→bật MEM→approve riêng→restart→đúng bot đọc memory; tắt/xóa→không dùng lại. Backend/LLM lỗi không hiện saved.
3. **M3 AI-off:** hai account adult synthetic, AI/MEM tắt→publish allowlist→discovery→invite/accept→một room→chat ACK→disconnect/replay→block/reveal revoke.
4. **Eligibility:** teen nháp được nhưng direct publish/invite/chat/reveal denied; unknown/under16 session blocked; fixture/query không đổi quyền real mode.
5. **Privacy:** linked source edit/withdraw/MATCH revoke đóng room→enable lại vẫn đóng; data deletion immediate deny→status→restore không resurrect; export chỉ owner scope.
6. **Voice:** user gesture, permission denied/cancel/timeout/success→review transcript→edit→send riêng; revoke khi uploading/STT pending; audio cleanup/TTL.
7. **UX recovery:** 401/409/410/429/offline/503, duplicateclick, long Unicode, 200% zoom, 7 viewports, focus/ARIA, reduced motion và no console private data.

Existing ACT01 tests tiếp tục giữ trong fixture test harness, không biến thành release gate production Activities; real mode cần test nó bị ẩn hoặc preview disabled theo Q01. Screenshots là evidence render, không thay chức năng/API tests hoặc physical-device checks.

## AI evaluation framework

Dataset tối thiểu **60 scenarios synthetic tiếng Việt**, khởi đầu 12/bot, chia 40 dev/20 heldout theo scenario family, không chia các lượt cùng hội thoại sang hai tập. Bao gồm hội thoại nhiều lượt, viết tắt/mơ hồ, sửa ý, lỗi/timeout, thiếu nguồn, contradictory memory, spoofed userId, prompt injection, bot switch, consent revoke và sensitive situations. Không dùng real private conversations; các case safety/handoff dùng nội dung tổng hợp, không tuyển teen cho test kỹ thuật.

Metadata mỗi case: id/bot/task/input turns/source fixtures/consent+eligibility snapshot/allowed tools/expected facts/forbidden actions/memory scope/source versions/required approval/expected terminal state/rubric dimensions. Output artifact không chứa private data thật. Có case adversarial scripted provider cho deterministic enforcement và case real model cho behavior; không đánh đồng hai kết quả.

| Baseline              | Cấu hình so sánh                                                                               | Cách đọc kết quả                                                                                                           |
| --------------------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| A                     | Một model explicit + instructions/version + bounded session history, không domain tools/memory | Chất lượng role/relevance cơ bản                                                                                           |
| B                     | A + read/proposal tools đúng allowlist                                                         | Cải thiện tool task; không gọi tool tùy tiện ở task chỉ cần chat                                                           |
| C                     | B + approved memory đúng owner/bot/consent                                                     | Đo context accuracy/recall/privacy; bot không được memory như Cầu Nối giữ context rỗng, không ép “cải thiện” bằng mở quyền |
| D — Future experiment | Specialist-as-tool cho task thất bại cụ thể                                                    | Chỉ so sau evidence nhu cầu; cùng task/model/budget where applicable, cộng latency/cost orchestration                      |

Giữ model, task set, maximum output/tool/deadline, environment và sampling settings có thể so sánh; chạy lặp 20% cases để thấy variance. Model change/prompt/tool/context-policy version change đều có report mới; no tuning trên heldout. Retry model lỗi không được xóa trial thất bại khỏi denominator.

Rubric1–5: role adherence, relevance, context/source accuracy, không hallucinate dữ kiện, tool selection/correctness, memory consent, context leakage, safe bot transition, response usefulness/calibration. Ghi task completed, latency toàn lượt/TTFT model nếu đo được/progress delay, input/output/reasoning/tool usage khi provider trả và cost per completed task. Không coi trust/confidence do model tự nói là score sự thật.

Hai người review độc lập một tập chung (ít nhất 20 cases), đối chiếu bất đồng và sửa rubric trước chấm heldout; LLM-as-judge chỉ trợ giúp, pin judge/version và xem calibration. Automatic checks cho owner/tool/receipts/forbidden outputs dùng dữ kiện fixture, không judge ngôn ngữ đơn thuần.

Ngưỡng thăm dò kế thừa technical PoC, cần Q08 chốt trước chạy: ≥80%ordinary tasks completed, không chiều chất lượng chính nào trung bình<4/5; **0 lỗi quan sát được** về leakage, unauthorized writes/social actions, stale memory/revoke và invented success. Bất kỳ lỗi quyền trong test set→Hold dù average cao. Báo sample size/variance; 0 observed errors không chứng minh tuyệt đối an toàn.

Matching eval riêng: exact oracle/hard filters trước, coverage/empty-rate/reason correctness và exposure distribution. Precision/nDCG@5 chỉ khi có nhãn synthetic relevance đủ rõ, không bịa nhãn để ra số. Mutual acceptance hoặc chất lượng quan hệ cần nghiên cứu người thật được duyệt riêng, không kết luận từ synthetic hoặc số tin nhắn.

## Performance và gates theo thời điểm

Workloads thăm dò: AI 1/5/20 concurrent với stub trước, real batch hạn mức sau; matching 100/1.000/10.000 profiles theo phân bố tags/goal/language; human 20/100 sockets với reconnect/retry/block. Ghi region/config/network/provider/version, p50/p95, error/timeout, queue delay, DB pool/locks, memory, quota và cost. Mục tiêu technical gợi ý AI p95≤15s no-tool short turn, matching≤1s@1k, chat commit→visible≤1s@20 sockets là **hypotheses**, chưa SLA.

| Gate                     | Phải đạt trước                                                                                  |
| ------------------------ | ----------------------------------------------------------------------------------------------- |
| G0 — baseline/contracts  | Unit/typecheck/build có evidence; teardown failure không giấu; DTO public allowlist             |
| G1 — riêng tư từ đầu     | Auth/ownership/eligibility/consent/CSRF + transaction races cho feature đang thêm               |
| G2 — AI tool/context     | SDK config/limits/cancel/output validation; TTL/replay và no default exporter canary            |
| G3 — social              | Two-actor mutual/quotas/message persist/replay/reveal/block/version races, no simulation        |
| G4 — hoàn thiện sản phẩm | Required screens/voice scope/error recovery, a11y/mobile, real-mode import graph                |
| G5 — release             | Heldout eval/security/load, deletion/processor/backup/restore/staffing, Q01–Q08, rollback drill |
