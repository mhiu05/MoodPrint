# Current architecture audit

Baseline: `main`, `984753389aa8bd4b3112b19a8beceb1e538fd659`, verified against origin on 2026-10-28. All source paths are repository-relative. Line numbers describe this baseline, not future implementation. New behavior proposed elsewhere is not present here.

## 1. Stack and architecture

**VERIFIED_SOURCE.** A modular FastAPI monolith uses SQLAlchemy/psycopg, Alembic and PostgreSQL; Python is `>=3.12,<3.13`. OpenAI Agents SDK is pinned to `0.24.0`. The frontend is React 19, TypeScript and Vite with React Router 7, plain CSS tokens, lucide icons and GSAP. There is no Supabase browser SDK, Redis client or product-tour dependency in the manifests. Evidence: [backend manifest](../../backend/pyproject.toml#L1-L25), [frontend manifest](../../frontend/package.json#L6-L40). Alembic head is `0015_context_privacy` ([migration](../../backend/alembic/versions/0015_context_privacy_context_privacy.py#L1)).

Browser → same-origin `/api/v1` FastAPI BFF → private `moodprint` schema; BFF → Supabase Auth/OpenAI/Voyage. `main.py:235–266` mounts the feature routers. `database/connection.py:21–30` configures bounded pooling, hides SQL parameters and disables prepared statements for pooler compatibility. Existing production support is one backend worker/replica (`backend/app/__main__.py:9–18`; `deploy/README.md:5`).

## 4. Social and moderation

Published-profile matching uses explicit public fields, not private chat/journals/memory. Draft → preview → publish checks versions/consent; current profile and pair authorization are revalidated with sorted user → pair → resource lock order. Discovery excludes blocked/ineligible/stale profiles, mints short-lived opaque references, and returns bounded candidate sets. Evidence: [social/routes.py:61–313](../../backend/app/modules/social/routes.py#L61-L313), [social/retrieval.py:45–138](../../backend/app/modules/social/retrieval.py#L45-L138), [social/service.py:71–153](../../backend/app/modules/social/service.py#L71-L153).

Required guest deny surface includes **reads as well as writes**: matching drafts/previews/publication, candidates/skips, connection requests, room lists/details/read markers/messages/events, peer references, identity reveal requests/grants/values, shared activities and staff endpoints. Prefix-only protection is insufficient: own private profile items and own identity settings share profile/identity naming with social resources. Inventory source: [social/routes.py:318–703](../../backend/app/modules/social/routes.py#L318), [social/notifications.py:37–124](../../backend/app/modules/social/notifications.py#L37), [moderation/routes.py:40–333](../../backend/app/modules/moderation/routes.py#L40), [activities/routes.py:42–315](../../backend/app/modules/activities/routes.py#L42).

`GET /social/summary` currently returns zero counts without enabled adult MATCH consent; guest design should deliberately preserve this harmless projection while performing no social queries (`social/summary.py:89–114`). Both sides of discovery/room gates must reject guest users to prevent malformed or old rows making a guest visible to a registered user.

Structured `icebreaker`, `coop_quiz` and `focus` activities are all connection-based (`activities/models.py:31–39`; `activities/routes.py:65–142`). No standalone quiz/focus API was found. Individual play through Rủ Rê is possible without falsely granting shared activity APIs.

Moderation has block/report/evidence and server-assigned `moderator`/`admin` roles. `require_staff()` re-reads role, requires recent password reauth (12 hours), returns 404 while moderation admin is disabled; route hiding is only UX. Evidence: [moderation/staff.py:19–51](../../backend/app/modules/moderation/staff.py#L19-L51), [moderation/admin_routes.py:23–64](../../backend/app/modules/moderation/admin_routes.py#L23-L64), [moderation/models.py:48–102](../../backend/app/modules/moderation/models.py#L48-L102). Reuse these gates for an admin-only feedback page with an independent feedback flag; do not grant roles from metadata or client input.

## 5. Data lifecycle and exhaustive footprint

`POST /data-deletions` increments versions, blocks private use, creates a durable job and clears current-process AI/exports. Account scope requires password reauth within five minutes, so it cannot simply be reused as a passwordless guest action. The worker claims 30-second leases, retries up to five attempts, deletes private content and invokes a private identity helper after marking user deleted. Exhausted work becomes failed and may release `deletion_pending`; a guest must still be expired independently. Evidence: [users/routes.py:37–67](../../backend/app/modules/users/routes.py#L37-L67), [users/lifecycle.py:35–186](../../backend/app/modules/users/lifecycle.py#L35-L186).

Normal active-DB retention runs once/minute, in bounded batches: chat/proposals, 90-day settled usage/run/mood/messages, activity data, 365-day safety records and matching aggregates; it does not delete expired guest identities. Evidence: [jobs/retention.py:19–205](../../backend/app/jobs/retention.py#L19-L205), [main.py:56–118](../../backend/app/main.py#L56-L118). Deletion deadlines therefore cannot depend on worker timeliness.

## 6. Frontend, product UX and routing

`main.tsx:1–11` always mounts `RealApp`; `RealApp.tsx:1918–1923` wraps `SessionRoot` in HashRouter. `SessionRoot:191–278` fetches `/session` before any page and shows AuthScreen on 401. A public landing is not currently implemented; this startup does not itself create a Supabase identity. Email callback is a real path `/auth/callback`, removes tokens from URL before rendering and returns to `/#/` (`Auth.tsx:17–33`). Preserve that ordering.

Navigation is Trợ lý / Cảm xúc / Tìm bạn / Tin nhắn / Cá nhân; settings and memory are separate routes. Social badge polling starts from Navigation regardless of future account kind. Shell routes are `/#/assistants`, `/#/self`, `/#/profile`, `/#/memory`, `/#/connect`, `/#/messages`, `/#/chat/:connectionId`, `/#/settings`, conditional `/#/admin/reports` (`RealApp.tsx:328–476`).

Current identity is warm off-white `#f8f9f6`, forest primary `#285c4b`, ink `#243a35`, system fonts, existing companion avatars and restrained motion ([tokens.css:1–59](../../frontend/src/styles/tokens.css#L1-L59)). Reuse Button/Dialog/StatePanel and focus handling ([UI.tsx:1–146](../../frontend/src/components/UI.tsx#L1-L146), [useMotionPolicy.ts:1–41](../../frontend/src/components/motion/useMotionPolicy.ts#L1-L41)). Rủ Rê/Cầu Nối links currently point into social routes and need guest-aware explanations.

No pervasive JWT/UUID/Supabase jargon was found in visible production labels; occurrences are predominantly code/comments. Real copy risks are context changes: `AIData.tsx:163–170` promises history for days/on another device, `RealApp.tsx:321–323` promises tomorrow's quota, `Privacy.tsx:108–139` uses registered deletion language/password workflow. These are false or unusable for a two-hour guest and need explicit variants, not a broad terminology rewrite.

## 7. Deployment and baseline observations

Caddy proxies `/api` with SSE flushing and falls back to `index.html` elsewhere; hashed assets immutable, other responses no-store ([deploy/Caddyfile:15–44](../../deploy/Caddyfile#L15-L44)). FastAPI also supports same-origin SPA serving and a strict CSP ([main.py:183–206,288–311](../../backend/app/main.py#L183-L206)). The Caddy HTML path does not set that CSP; live root GET showed no CSP header. Any CAPTCHA or tour release must validate both serving modes rather than assume one header policy.

AWS release polling verifies exact-main CI and image attestations; hosted migrations are a separate approval workflow, never startup work ([deploy/aws/README.md:1–7](../../deploy/aws/README.md#L1-L7), [alembic/env.py:60–82](../../backend/alembic/env.py#L60-L82)). Adding public routing does not require new AWS services. Production AWS Region/paid-plan/spend settings were not queried because no AWS changes are proposed or authorized.

**VERIFIED_RUNTIME read-only:** live root rendered login; desktop and 390×844 captures inspected; automated axe reported zero violations on that login screen only. Root, `/auth/callback`, health live/ready returned HTTP 200 and no-store. No login/signup/AI/feedback action was sent to production. No live build SHA or authenticated journey was verified.

**VERIFIED_RUNTIME Supabase metadata:** connected project's URL matched local configuration without printing secrets. Catalog-only SELECTs observed revision `0015_context_privacy`, 39 `moodprint` relations including `alembic_version`, RLS enabled on all, SELECT denied to `anon` and `authenticated`, 38 runtime `ALL true/true` policies plus one runtime SELECT policy. Runtime is neither superuser nor BYPASSRLS. Both private helpers are SECURITY DEFINER with empty search path; callable by runtime, not anon/authenticated. This is runtime-role RLS, **not end-user row ownership RLS**. No personal records or Auth users were read. Data API schema exposure and every non-SELECT privilege were not independently checked.

Read-only query forms used: `SELECT version_num FROM moodprint.alembic_version`; `pg_class`/`pg_namespace` + `has_table_privilege`; `pg_policies` grouped by roles/cmd/qual/with_check; `pg_roles`; `pg_proc` + `has_function_privilege`. One helper query transport failed once, then its retry succeeded. Anonymous-enabled setting is **USER_REPORTED**, not re-verified through a settings-changing operation. Anonymous hosted creation/deletion behavior remains untested.
