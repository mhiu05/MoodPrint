# S-07 — Shape of the image call

Status: **UNMEASURED / BLOCKED** (same reason as S-06).

Question: does a `gpt-6-luna` image input travel through `Runner` as an `input_image` item with a
data URL, or must `evidence/reader.py` call `AsyncOpenAI.responses.parse` directly?

Offline decision recorded so far: the reader is a single-request multimodal *service* with a
structured output schema and no session, tools or handoff, so the direct
`responses.parse(..., store=False, max_output_tokens=...)` form is implemented first and goes
through the same budget-guarded HTTP transport. `Runner` is only needed if the direct form is
rejected by the live API (L-AG-04). Size/format limits are enforced locally before any upload.
